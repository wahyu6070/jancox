# Jancox-tool

Unpack/repack Android ROMs. Being rewritten from shell + Python into a single Rust binary (`jancox`) for Android, Linux and Windows.

## Layout

- `crates/jancox-core/`: library with the ROM logic.
  - `br.rs`: brotli compress/decompress (`brotli` crate). `Encoder::finish()` must be used: `brotli::CompressorWriter` swallows errors from its final flush.
  - `sdat.rs`: `*.new.dat[.br]` -> image (sdat2img). `dat.rs`: image -> `*.new.dat[.br]` (img2sdat), streaming through brotli.
  - `fs/`: read-only filesystem readers behind the `Filesystem` trait. `fs/ext4.rs` is our own ext2/3/4 reader (extents, block maps, htree dirs read linearly, inline data, xattrs in-inode/block/EA inode). `fs/erofs.rs` reads EROFS (compact/extended inodes, flat plain/inline and chunk-based files, shared/inline xattrs, long prefixes also from the packed inode); `fs/erofs/z.rs` does compressed files, ported from erofs-utils `lib/zmap.c` + `lib/decompress.c` (MIT side of their dual license): compact/full indexes, extent records, big pclusters, ztailpacking, fragments, partial refs, lz4 (our `lz4.rs`, partial decoding), MicroLZMA (lzma-rust2 raw decoder, props = !first byte), raw deflate (flate2), zstd (ruzstd), shifted/interlaced plain pclusters. Files are read forward one whole extent at a time; damaged images must give errors, never panics or huge allocations (test `damaged_images_fail_cleanly`). `fs::Window` reads a byte range of a file, e.g. an image stored in a zip.
  - `extract.rs`: extracts an ext4 or EROFS image (from a path, or any `Read + Seek` via `extract_reader`) to `<out>/<part>/` and writes `<out>/config/<part>_{fs_config,file_contexts,symlinks,info}`. Paths are device paths built from the mount point, which comes from the volume name (`/` = system-as-root); `last_mounted` is unreliable (old Jancox overwrote it). EROFS images have no volume name: a root with `system/build.prop` means system-as-root (`/`). Paths with whitespace can't be expressed in fs_config and only get a warning.
  - `fs/mkerofs.rs`: our uncompressed EROFS writer (superblock + shared xattrs + inodes from block 0, compact inodes unless ids/sizes need extended ones, FLAT_INLINE tails, sorted dirs incl. `.`/`..`, sb checksum); `build.rs` picks it when `<part>_info` says `fs_type=erofs`, and sizes EROFS images to fit their content.
  - `fs/mkext4.rs`: our ext4 image writer (no journal, no flex_bg, linear dirs, 256-byte inodes, extents with multi-level trees, all-zero file blocks left as holes, xattrs in-inode or in one xattr block; with `shared_blocks` in the `<part>_info` features, identical file blocks are stored once like e2fsdroid, which gives the same block count as the original ASUS images). `build.rs`: folder + metadata -> `mkext4::Node` tree; the folder decides which files exist, new entries get Android-like defaults and inherit their directory's label, known entries without a label stay unlabeled.
  - `factory.rs`: fastboot ROMs (Pixel factory zip with a stored `image-*.zip`, or an image zip on its own), stored zip entry ranges, `super_empty.img` groups (liblp), the vbmeta disable-verity flags.
  - `payload.rs`: A/B OTA `payload.bin` (header, `DeltaArchiveManifest` via `proto.rs`, our hand-written protobuf decoder/encoder). Full OTAs only (REPLACE, REPLACE_BZ, REPLACE_XZ, ZSTD, ZERO, DISCARD; incremental ops are refused). `pipeline` (one reader, N workers, results in order) drives `dump_partition` (checks blob and partition SHA-256) and `encode_image` (2 MiB REPLACE_XZ chunks, xz without check as AOSP). `copy_partition` copies ops+blobs of unchanged images; `encode_manifest` keeps the old manifest/partition fields (drops hashtree/FEC/COW estimates of rebuilt ones); `write_payload` signs: metadata signature over header+manifest, payload signature over header+manifest+blobs (not the metadata signature), FILE_HASH over everything. Parse leniently: ASUS puts its own strings at manifest fields 16+ (16 is `partial_update` in AOSP).
  - `sign.rs`: RSA PKCS#1 v1.5 (`rsa` crate) with the AOSP test key in `keys/` (or `sign.key`/`sign.cert`), `sign_zip` = `signapk -w` (detached PKCS#7 in the zip comment; hash SHA-1 when the cert is sha1WithRSA, as recovery decides), base64.
  - `ota.rs`: OTA zip pieces: `ota-property-files` rewrite in `metadata`/`metadata.pb`, planned data offsets of stored entries (`local_header_len` probes the zip writer), fastboot flash scripts.
  - `lp.rs`: liblp metadata (`super.img`: 4096 reserved, geometry + backup, metadata slots + backups; `super_empty.img`: geometry at 0), SHA-256 checked, backup used when the primary is bad; `relayout` gives each partition one aligned linear extent; `SuperReader` reads raw or sparse. `sparse.rs`: random-access `SparseReader` and `write_sparse` (RAW / zero FILL / DONT_CARE). `fs::Segments` reads a partition's extents as one stream.
  - `tar.rs`: tar reader (ustar, GNU long names, pax path) and writer. `superrom.rs`: super ROMs (`format=super`, `container=tgz|tar|zip`, `super_map` = partition:liblp name): unpack keeps the archive in `rom/` except super.img (partitions to `partition/`, metadata + non-fs partitions to `super/`); repack builds a new super.img (sparse like the original), patches vbmeta, renews Xiaomi CRC lists (`xiaomi.rs`, a port of the ROM's `flash_gen_crc_list.py`, checked identical to the script) and writes the archive in the original entry order.
  - `rom.rs`: work folder = where jancox runs (`-w`): `input/`, `output/`, `jancox.prop` (made by `init`; `brotli.level`, `zip.level`, `payload.output`, `payload.xz_level`, `sign.key`/`sign.cert`, read by `repack`, CLI flags win), `rom/`, `partition/<part>/` + `partition/config/`. `unpack` (zip -> brotli -> sdat2img -> extract, streaming, state in `<work>/jancox_rom`; warns once when the storage can't hold symlinks, they stay in `_symlinks`), `repack` (build -> img2sdat -> brotli straight into the zip; grows full partitions and updates `dynamic_partitions_op_list` on dynamic ROMs), `cleanup` (never touches `input/`). Fastboot ROMs (`format=fastboot` in `jancox_rom`): unpack reads the logical partitions from `super_empty.img` straight from the inner zip, and the rest of the image zip goes to `rom/<image zip without .zip>/`; repack rebuilds the images, checks the super groups, patches the vbmeta flags, then writes the image zip (original entry order) and the outer zip. Payload ROMs (`format=payload`): unpack dumps each partition, extracts the logical ones (dynamic groups in the manifest) that are ext4/EROFS, and keeps the rest as `rom/payload/<name>.img`; repack (`payload.output` = payload/fastboot/both) rebuilds the logical partitions, copies unchanged images from the input zip (still needed in `input/`), patches vbmeta, writes a signed OTA zip (every entry stored so the property-file offsets are known; checked after writing, then `sign_zip`) and/or a fastboot zip.
  - Verify builder/repack changes with a round trip: extract -> build -> `e2fsck -fn` must exit 0 -> extract again -> folder, fs_config, file_contexts and symlinks identical. The crDroid surya ROM (4 ext4 partitions, `.new.dat.br`, dynamic) was used for end-to-end tests with `-w work`; it is no longer on disk (re-download it into `input/` to re-verify the sdat path).
  - super.img: the POCO F4 (munch) V14.0.6.0.TLMMIXM fastboot tgz (6 GB, sparse super, ext4) is in `work/munchf/input/` and the same version's recovery OTA in `work/munchg/input/` (gitignored); their partitions extract identical. Check a repacked super with `simg2img`, an independent liblp parse (checksums, no overlapping extents), `e2fsck -fn` on each partition, a round trip, and the ROM's `flash_gen_crc_list.py` (Python 3 port by sed) against our CRC lists. Unpack ~1.5 min, repack ~3 min.
  - payload.bin: every dumped partition must match `new_partition_info.hash`. The ASUS ROG Phone 5 full OTA (ZS673KS 33.0210.0210.200, 3.6 GB, ext4, dynamic, REPLACE_XZ/BZ) is in `work/rog/input/` (gitignored): unpack ~1 min, `jancox payload` dump ~40 s, repack `-t both` ~3 min. Check a new payload with AOSP `paycheck.py <zip> --check --type full --key testkey-pub.pem` (update_engine `scripts/`; its `_CheckElemNotPresent` must skip fields missing from the proto, e.g. `old_kernel_info`), the zip signature with `openssl cms -verify -binary -inform DER -noverify` over the file up to the comment length, and a round trip unpack.
  - EROFS: verify with erofs-utils 1.9.4 (`fsck.erofs`, `--extract` as the reference; 1.7.1 truncates chunk-based files; 1.9.4 mkfs segfaults with `--compress-hints`, use 1.7.1 for mixed algorithms) and, where sudo works, `mount -t erofs -o ro,loop` (the Ubuntu 6.8 kernel has lz4 and deflate, not lzma). The Redmi Note 13 4G OTA (sapphire, lz4 EROFS, 4.8 GB) is in `work/xm/input/` (gitignored): unpack ~1.7 min. The Pixel factory zip (cubs, 15 GB, EROFS, fastboot) was in `work/pixel/input/` (gitignored, no longer on disk); an unpack took ~1 min, a repack ~4 min.
  - Verify extractor changes against `debugfs` (`stat` + `ea_get` for long labels, `rdump` for contents). `debugfs rdump` pads inline-data files to 60 bytes, so compare those with the source tree instead.
- Only sdat2img and img2sdat live in their own repos ([sdat2img-rust](https://github.com/wahyu6070/sdat2img-rust), [img2sdat-rust](https://github.com/wahyu6070/img2sdat-rust)), used as git dependencies pinned by tag: fix them there, tag a new version, then bump the tag in `Cargo.toml`. Everything else (brotli, the image extractor, ...) is written in this repo.
- `crates/jancox-cli/`: the `jancox` binary; one binary with subcommands (`init`, `unpack`, `repack`, `cleanup`, `extract`, `build`, `payload`, `super`, `sdat2img`, `img2sdat`, `brotli`).
- `android/`: the Magisk/recovery flashable module; it is only an installer. `customize.sh` picks `bin/<arch>/jancox` for the device and installs it to `/system/bin/jancox`. The old shell + Python tool was removed (last shipped in v2.5, still in git history).
- `build.sh`: cross-compiles all targets (zig + cargo-zigbuild for Linux/Windows, Android NDK for Android). `./build.sh module` builds the Android targets and packs `android/` + `bin/<arch>/jancox` into `dist/Jancox-tool-android-<version>.zip`.

## Rules

- `update.json` and `changelog.md` must stay at the repo root on `master`: installed modules poll them through the raw GitHub URL in `android/module.prop` (`updateJson`).
- Before committing, run `cargo fmt`, `cargo clippy --all-targets -- -D warnings` (zero warnings) and `cargo test`.
- Commit `Cargo.lock`; `build.sh` builds with `--locked`.
- On a release, bump `version` in `Cargo.toml`, `version`/`versionCode` in `android/module.prop`, and `update.json` together.

## Git workflow

- This repo only uses one branch: `master`. Work and commit directly on `master`; don't create feature branches.
- Don't rename `master` to `main`: the `updateJson` URL points at `refs/heads/master`.
- The repo was renamed from `Jancox-tool-android` to `jancox` (2026-09-25). GitHub redirects the old URLs, and installed v2.5 modules still poll the old `updateJson` URL through that redirect: never create a new repo named `Jancox-tool-android`. Use `wahyu6070/jancox` in new URLs.
